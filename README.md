# Go语言CPU调度和内存协同模型

本仓库是Go语言CPU调度和内存协同模型项目仓库，该项目的主要目标是对目标场景实现单进程峰值内存降低30%或者理论极限，同时保证对编译时长的影响小于5%，CPU性能的影响小于1%、不出现OOM的问题。交付与验收标准如下表所示。

## 近期规划（2026年6月）

1. 目标场景性能收益的评估——**李清伟、茹祥程**
   1. 基于原有针对actor-demo的测试方法以及在华为目标场景中的测试经验形成测试工具链，测试包括CPU占用、程序执行效率、内存占用量、GC相关的指标（GC触发次数、GC扫描耗时、每次GC触发前后的内存占用）
   2. 对目标场景的代码特征的实证，分析目标场景下可以进行内存优化的模式。
   3. 对目标场景CPU和内存使用情况进行采样和建模，记录内存使用、垃圾回收、CPU占用三者随时间的变化情况，可以形成折线图的形式。
2. 对CEA进行框架性改进——**丁伯尧、茹祥程**
   1. 过程间分析的进一步扩展，支持对于摘要中记录的参数的值流向"堆"这一信息进一步的细粒度划分，将这里的"堆"分为三类：真正无法确定生命期的堆（EscapeHeap），生命期在被调用函数内的"堆对象"（EscapeWithinFunc），生命期在调用者函数中的"堆对象"（EscapeToCaller）。参考[src/cmd/compile/internal/escape/EscapeToCaller-interprocedure.md.md · cea · vm / golang / work / go1.24.2 · GitLab](http://202.38.78.31:1480/vm/golang/work/go1.24.2/-/blob/cea/src/cmd/compile/internal/escape/EscapeToCaller-interprocedure.md.md?ref_type=heads)
   2. 完善接口描述与设计，允许通过一些代码中注解的形式指定部分优化方法（例如指定区域内存管理的粒度）
3. 相关文献的调研——**丁伯尧、李清伟、茹祥程**
   1. CPU和内存的多目标优化/协同优化的相关工作
   2. 针对actor模型的内存优化工作
   3. 基于LLM的程序分析等工作，可以考虑利用LLM添加优化注解

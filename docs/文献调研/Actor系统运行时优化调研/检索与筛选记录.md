- 调研日期：2026-09-15
- 种子论文：*Improving the Performance of Actor Model Runtime Environments on Multicore and Manycore Platforms*

## 3. 纳入标准

至少满足一项：

1. 位于种子论文参考文献或直接引用链中；
2. 对 Actor 调度、mailbox、消息传递、对象所有权、GC 或执行粒度提出明确机制；
3. 提供实证结果或可用于当前项目的语义/实现约束；
4. 为实验设计提供具有代表性的通信拓扑和基准。

## 4. 排除或降低优先级的标准

- 只把 Actor 当作应用背景，没有运行时优化机制；
- 主要处理分布式一致性/容错，但与进程内内存和调度关系很弱；
- 只回收不可达 Actor 实体，而目标场景主要是长生命周期 Actor 内的事务对象；
- 只有搜索摘要、无法核对题名/作者/出版信息；
- 与种子论文直接引用关系存在，但内容只是平台背景，无法支持当前方案。

## 7. 质量控制

- 每个已下载文件检查 PDF magic bytes、`pdfinfo` 页数和首页题名，避免把 HTML 错误页当作论文。
- DOI 以论文首页、DBLP 或出版社页面至少一个权威来源核对；冲突时优先会议论文 DOI。例如 SOTER 的 PPoPP 论文 DOI 为 `10.1145/1941553.1941566`，SIGPLAN Notices 转载记录另有 DOI，不混为同一出版入口。
- 性能数字仅在论文所述工作负载范围内报告，并保留“最高”“部分场景”“可能退化”等限定。
- 引用数只报告同一 OpenAlex 快照；缺失值不记为 0。
